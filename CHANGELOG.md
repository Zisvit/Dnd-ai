## [1.1.0] - 2026-10-17

Бэклог качества из 8 пунктов: инфраструктура проверок, целостность промптов,
кэш моделей, fail-fast 401, локи и расширение тестов.

### Добавлено

- Инфраструктура кода: ruff (`E4/E7/E9/F/W/B/UP/I/FA102`, длина строки 100)
  и mypy в CI; покрытие с порогом 65% на обеих версиях Python-матрицы.
- Целостность промптов: манифест sha256 `dndai/prompts/checksums.json`,
  предупреждение в рантайме при расхождении, строгая сверка внутри собранного
  wheel в CI (`dndai/core/config/prompt_integrity.py`).
- `dndd --list`: список сохранённых сессий (число сообщений, размер, дата;
  до 50; битый файл помечается). Работает без ключей и не создаёт дом данных.
- Кэш `get_ollama_models()`: TTL 300 секунд, отключается `OLLAMA_CACHE_TTL=0`,
  кэшируется только непустой успех; есть `reset_ollama_models_cache()`.
- Fail-fast 401: провайдер, отклонивший ключ, пропускается на 60 минут
  (сообщение `api.auth_skipped`); эндпоинты Ollama не затрагиваются.
- Тесты: `tests/test_world.py`, `tests/test_party.py`, `tests/test_rpg.py`,
  `tests/test_commands.py`, `tests/test_locks.py`, `tests/test_settings.py`,
  `tests/test_prompt_integrity.py`, `tests/test_package.py` (всего 320 тестов,
  покрытие 70.9% на Python 3.13).

### Исправлено

- Команды удаления не работали: `!npc удалить X`, `!заклинание удалить X` и
  `!статус-эффект удалить X` добавляли объект с именем «удалить», а
  `!макрос удалить X` молча ничего не делал. Теперь формы `удалить`/`удал`
  удаляют (у `!npc` также `del`/`rm`); закреплено регресс-тестами.
- Гонки потоков: `load_blacklist` обновляет словарь in-place и сбрасывает метку
  auth-фейла; `is_blocked` читает блокировку одним просмотром под локом;
  инкременты статистики защищены `_stats_lock`.

### Изменено

- Стилевые автофиксы ruff по всем модулям (сортировка импортов и т.п.) без
  изменения поведения; четыре star-фасада исключены per-file-ignores.
- В wheel добавлен `prompts/*.json` (манифест целостности) в package-data.
- В `dndai/api/__init__.py` зафиксирован load-bearing порядок star-импортов
  и характеризующий тест (`tests/test_package.py`).

### Примечания

- Остаточный риск: строгость mypy неполная — тела функций без аннотаций не
  анализируются (`annotation-unchecked`), FA100 выключен, target 3.10 выбран
  вынужденно (mypy не поддерживает 3.9).
- Лок статистики — страховка: потери инкрементов в стресс-эксперименте
  (80–192 тыс. операций) не наблюдались; регресс-тесты фиксируют инвариант
  сводки и красный rebind-тест `load_blacklist`.

## [1.0.1] - 2026-10-17

Сплошное ревью кода: исправлены 8 дефектов, добавлены регресс-тесты.

### Исправлено

- Стриминг: обрыв потока сохраняет уже показанный текст и не повторяет
  запрос после первой порции; маркер обрыва выводится только на экран
  (`on_token`) и не попадает в историю сессии.
- Статистика: один неудачный стрим — одно событие (отказ/пустой ответ
  больше не учитываются дважды).
- Принтер стриминга: одиночный `<` не теряется при разбиении между токенами.
- Первый ход: при сбое генерации созданная партия сохраняется в сессию
  (если файла ещё нет) и не теряется.
- `compress`: локальная сводка не портит разметку `{{NPC}}`;
  API-суммаризация принимает 3-компонентный результат `api_request`.
- Модели: принудительная модель ищется и в tier-таблицах провайдеров
  (warning, если не найдена).
- Сессии: чтение в UTF-8, при битой кодировке — откат на `.bak`
  с предупреждением.

### Добавлено

- Регресс-тесты на все исправления: `tests/test_api.py`,
  `tests/test_compress.py`, `tests/test_main_flow.py`,
  `tests/test_i18n.py` (паритет ru/en: 364 ключа, 0 расхождений);
  дополнения в `tests/test_output.py` и `tests/test_persistence.py`
  (216 тестов в сьюте).

## [1.0.0] - 2026-10-17

Первый публичный релиз: установка как pip-пакета, единый дом данных, версии.

### Добавлено

- Пакет `dndai` (pyproject.toml), консольная команда `dndd` и запуск
  `python -m dndai`.
- `--version` / `-V`, `--copy-prompts`; коды возврата 0/1/2/130.
- Каталог данных `~/.dnd_ai` (переопределяется `DND_AI_HOME`): сессии,
  blacklist, история ввода. При запуске из старой раскладки репозитория
  данные (`data/`, `dnd_sessions/`) переносятся автоматически один раз
  (маркер `.migrations.json`, источники не трогаются).
- Тесты: изоляция дома данных (`tests/conftest.py`), страж версии
  (`__version__` ↔ CHANGELOG), CLI-тесты.
- CI (GitHub Actions): тесты на Python 3.9/3.13 + сборка wheel с проверкой
  промптов внутри и смоук-установкой.

### Изменено

- Точка входа: `main(argv) -> int` с argparse; имя сессии валидируется
  (без разделителей пути и `..`, до 64 символов).
- Промпты: приоритет `$DND_PROMPTS_DIR` → `~/.dnd_ai/prompts` → пакет;
  автокопии при запуске нет, сидирование — `--copy-prompts`.
- `.env` читается только по явным путям: процесс → `./.env` →
  `~/.dnd_ai/.env` (no-arg `load_dotenv()` убран).
- Установка: `install.sh` создаёт venv и shim `dndd` без хардкода путей;
  `requirements.txt` заменён pyproject.toml.

### Удалено

- Мёртвый код и шимы: `get_data_dir`, `load_api_keys`, дубль `load_prompt`,
  `STATIC_MODELS_FILE` и `data/static_models.txt`.

### Исправлено

- Двойной `❌` в сообщении об отсутствии ключей; сообщение указывает путь
  к `.env` и вариант с локальной Ollama.
- Никакой записи на диск при импорте модулей — каталоги создаёт точка входа.
